# Sideline

Extract code comments into a YAML store, keeping the code and the comment data separate. Reversible and idempotent.

Sideline lifts the comments out of your `.cs`, `.ts` and `.js` files into a single `sideline.yaml` at the repo root, leaving every non-comment byte of the code untouched. Run it in reverse and the comments go back exactly where they were.

```bash
sideline extract    # code -> stripped, comments -> sideline.yaml
sideline restore    # comments -> back in the code
```

## Requirements

Node 20 or newer. This repo pins 24 via `.nvmrc`:

```bash
nvm use
```

## Install

```bash
npm install && npm run build && npm link
```

## How comments stay attached to code

Line numbers are useless as identity — anything above a comment shifts it. So each comment is anchored to the **content** of the code around it: the normalised text of the three code lines before and the three after.

Normalisation trims and collapses whitespace, which is what gives you these guarantees:

| Change to the code | What happens |
| --- | --- |
| Comment moves down 50 lines | Placed. No re-anchor. |
| Block reindented | Placed. No re-anchor. |
| CRLF converted to LF | Placed. No re-anchor. |
| Line directly above deleted | Placed, and **re-anchored** |
| Line directly below deleted | Placed, and **re-anchored** |
| Both sides rewritten | **Orphaned** — kept in the store, flagged |
| Two equally plausible sites | **Orphaned** — never guessed |

An orphaned comment is never deleted and never placed somewhere it might not belong. `sideline orphans` lists them for triage.

## Reversibility

`restore(strip(f)) == f`, byte for byte. That is asserted as a property test over the whole fixture corpus, and it covers the details that usually break this kind of tool:

- CRLF and LF line endings, preserved per file
- UTF-8 BOMs and UTF-16LE
- Files with no trailing newline
- Blank-line runs around a stripped comment block
- Trailing comments (`x = 1; // why`) and inline ones (`foo(/* a */ 1)`)

Stripping collapses `blankAbove + block + blankBelow` down to `max(blankAbove, blankBelow)` blank lines, so the stripped code keeps sensible spacing, and both counts are recorded so the original is rebuilt exactly.

**Every extraction is verified before anything is written.** Sideline rebuilds the original in memory and compares it character for character; on a mismatch it skips the file and reports it. A lexer bug therefore costs you a skipped file, not corrupted source.

## Idempotency

`extract → restore → extract` produces a byte-identical `sideline.yaml` *and* byte-identical stripped code, for as many cycles as you like.

This needs more than content hashing. After an extract the code has zero comments — so a second extract must not conclude that you deleted every comment. The store records each file's state explicitly:

- **`extracted`** — the file was expected to have no comments. Anything found is a new addition; existing records are kept and re-anchored against whatever the code became.
- **`restored`** — the file was expected to have its comments. What is in the file is authoritative, so a record with nothing matching it means you genuinely deleted that comment.

## Incremental runs

`sideline extract` reads `git status` plus anything committed since the store was last written, so a normal run only touches what changed. `--all` forces a full scan.

- A **renamed** file keeps its comment ids, via git's rename detection.
- A **moved** file git did not record as a rename is found by matching its comments against unclaimed files (60% threshold).
- A **deleted** file is marked orphaned with its comments retained, not dropped.

## Which comments get extracted

By default Sideline leaves anything in the code that could change what the build does, and extracts the rest.

| Class | Default | Examples |
| --- | --- | --- |
| `pragma` | **kept in code** | `@ts-expect-error`, `eslint-disable`, `/// <reference>`, `//# sourceMappingURL`, `prettier-ignore`, shebang |
| `region` | **kept in code** | `//#region`, `//#endregion` |
| `doc` | extracted | C# `///` XML docs, JSDoc `/** */` |
| `license` | extracted | Copyright, SPDX, `@license` |
| `ordinary` | extracted | everything else |

Every class is configurable. Files marked `// <auto-generated>` are skipped entirely.

## Configuration

`sideline init` writes a documented `sideline.config.yaml`:

```yaml
include: ["**/*.cs", "**/*.ts", "**/*.js"]
exclude: ["**/node_modules/**", "**/bin/**", "**/obj/**", "**/dist/**", "**/*.min.js", "**/*.d.ts"]
store: sideline.yaml
anchorWindow: 3
fuzzyThreshold: 0.8
preserve:
  pragma: true
  region: true
  doc: false
  license: false
  custom: []      # extra regexes to leave in the code
skipAutoGenerated: true
```

## Commands

```
sideline extract [paths...]   Lift comments out of the code into the store
sideline restore [paths...]   Put the stored comments back into the code
sideline status               Per-file: extracted / restored / drifted / orphaned
sideline check                Exit 2 if the working tree is not what the store describes
sideline orphans [--prune]    List comments with no home; optionally delete them
sideline init                 Write a default config file
```

Flags: `--all`, `--dry-run`, `--json`, `--no-verify`, `--config PATH`.

`check` is the CI gate. It fails if a file has drifted, has gone missing, has comments that were never extracted, or is currently in restored state.

## Lexing

Comments are found with a real scanner per language, not a regex, because `//` inside a string is not a comment.

- **C#** — regular, verbatim (`@"…"`), interpolated (`$"…"`), both verbatim-interpolated spellings, raw strings (`"""…"""`) with N-quote delimiters and the N-dollar interpolated form, char literals.
- **TS/JS** — strings, template literals with nestable `${}` holes, and regex-literal-versus-division resolved from the preceding significant token.

## Known limitations

- `.jsx` and `.tsx` are unsupported. A `.js` file containing JSX is **skipped with a warning** rather than corrupted, since `//` is literal text inside JSX.
- Files mixing CRLF and LF are skipped — they cannot be rebuilt byte-exactly.
- A single root `sideline.yaml` grows large on a big repo. `store` can relocate it; sharding is not implemented.
- Inline comments mid-expression store a column offset into their line and orphan sooner than line-anchored ones when that line changes.
- Concurrent edits to `sideline.yaml` can conflict on merge. Deterministic per-file grouping keeps conflicts localised but does not eliminate them.
